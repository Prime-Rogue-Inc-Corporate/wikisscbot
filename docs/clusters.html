Address clusters

An address in this archive is a network exit, not a person, and one exit can use several addresses. This page shows which addresses carry the same traffic and which blocks replaced which. Reviewed 12 November 2026.

Four ways one thread reaches two addresses

  • Pool. Two addresses edit the same page within the hour of each other, again and again. One exit, several addresses.
  • Renumbering. One block goes quiet, another starts, and pages from many unrelated threads carry over.
  • Parallel exits. The same thread on two addresses in the same weeks, without enough handoffs to call it a pool.
  • Reappears later. A thread stops on one address and turns up months or years later on another.

The first three describe the network. Only the fourth says anything about an editor, and then only that the same routine moved.

Limits

  • An edit from a government network is not evidence of who made it, or that it was made in an official capacity. Most addresses are shared gateways used by hundreds or thousands of people.
  • Only metadata is used: page titles, edit summaries, sizes and timestamps. No diff text is read.
  • The cut-offs were set to recover cases first found by hand. There is no ground truth to test them against.
  • About half of all edits are one-off touches that belong to no thread and cannot be matched.
  • Live events and much-edited pages draw several people to the same place, and two people can share an interest.
  • The across-years tables were computed from 63,623 edits (2008–2025); the inside-each-year tables from 63,623 edits (2008–2025). They are recomputed by hand, not on every build.
